# 服务员小费收入管理 H5：UI 原型设计说明

## 1. 目的与边界

本说明用于在 H5 开发前制作并确认可点击的移动端原型。它定义原型应参考什么、应验证什么，以及不应从模板带入什么。

- 主需求文档定义产品功能与验收：[H5 小费收入管理需求文档](../H5小费收入管理需求文档.md)。
- [Apple Design 参考文档](apple.design.md)定义视觉语言的基础。
- 本文定义页面结构、模板使用边界和需要验证的交互，不新增产品功能。

## 2. 模板策略

采用“组件底座 + 布局参考 + 产品专属流程”的组合，而非整套套用第三方模板。

| 来源 | 使用方式 | 不采用的内容 |
|---|---|---|
| [Apple iOS / iPadOS UI Kit](https://help.figma.com/hc/en-us/articles/24037724065943-Start-designing-with-UI-kits) | 作为导航、底部抽屉、输入控件、日期选择、开关、按钮与图标的组件底座 | Apple 官网式营销页、全屏产品宣传版式 |
| [Figma Mobile UI Kit](https://www.figma.com/templates/mobile-ui-kit/) | 参考移动端 Auto Layout、表单状态、列表层级和组件组织 | 通用社交、聊天或营销页面 |
| 财务记录类 UI Kit | 参考金额输入、收入汇总卡、历史列表和统计的布局结构 | 预算、投资、转账、储蓄目标、账户认证等非核心功能 |

模板仅用于提高视觉一致性和设计速度。页面流程、字段优先级与计算说明必须以服务员“下班后 20–30 秒记录一班净收入”的任务为准。

## 3. 视觉方向

### 3.1 应保留

- 系统字体优先：`SF Pro / system-ui / -apple-system`。
- 单一蓝色交互色：`#0066CC`；蓝色只用于主要操作、链接、选中与焦点。
- 浅色中性画布：白色、`#F5F5F7` 与轻微表面区分；不用渐变作为主视觉。
- 深色文字、大号金额、清晰的数据对齐；金额使用等宽数字样式。
- 圆角有层级：输入与小组件使用较小圆角，主要操作可使用胶囊形；不以阴影制造层级。
- 最小功能动效：底部抽屉、保存反馈、删除撤销只使用帮助理解状态变化的短动画。

### 3.2 不应使用

- 紫色渐变、彩色装饰图标、拟物插图或复杂仪表盘。
- 为了“看起来专业”而放入大面积趋势图、预算进度、投资组合或空泛的数据卡。
- 小字号承载关键金额，或使用低对比度文字。
- 首屏堆叠多个 CTA；用户每次打开应一眼找到日期与记录入口。

## 4. 原型必须包含的页面

| 页面 | 首要问题 | 必须展示的内容 |
|---|---|---|
| 月历首页 | 用户能否一眼知道本月收入，并马上开始记录？ | 月份切换、每日净收入、今日／本周／本月简要汇总、点击日期 |
| 当天详情抽屉 | 某天无记录、有一班或有多班时是否清楚？ | 当日净收入、班次卡片、新增班次、编辑与删除入口 |
| 新增／编辑班次 | 用户能否在 20–30 秒内完成默认记录？ | “Record Shift”标题、日历带入的只读日期副标题、工时、现金小费、信用卡小费、可选手动 Tip-out、实时净收入、固定保存按钮、更多选项 |
| 餐厅设置 | 默认薪资和规则是否能减少日常重复输入？ | 餐厅名称、薪资方式与金额、常用餐厅、Tip-out 默认规则 |

## 5. 班次表单的信息层级

顶部以“Record Shift”加日历带入的只读日期副标题呈现日期，例如“Thursday, August 21”；日期不是表单行，也不能在这里修改。

默认可见字段必须限制为：餐厅、直接填写的工作时长、现金小费、信用卡小费、可选手动 Tip-out，以及净收入与实际时薪。

“更多选项”中才出现：可选 Lunch／Dinner 标签、Clock in／Clock out（与直接工作时长二选一）、未付休息时间、其他收入、销售额、信用卡到账方式、自动 Tip-out 规则和备注。

Lunch／Dinner 不应作为必填班次类型，也不应在首版提供更多预设类型；它只服务于想比较午晚班收入的用户。

自动 Tip-out 的规则快照与净收入计算说明必须可展开查看，但不应阻塞保存或占据默认录入界面。

## 6. 可点击验证路径

### 路径 A：首次使用

创建一个默认餐厅 → 从月历选择今天 → 录入一班收入 → 保存 → 看到当天净收入更新。

### 路径 B：默认快速记录

从月历选择日期 → 填工时、现金小费、信用卡小费 → 查看净收入 → 保存。目标是熟练用户 20 秒，验收不超过 30 秒。

### 路径 C：复杂但可理解的记录

选择另一个餐厅或启用自动 Tip-out → 填必要计算基数 → 展开核对规则快照 → 保存；或输入跨午夜开始／结束时间与可选未付休息时间 → 核对跨日标记和有效工时。

## 7. 原型验收清单

- 用户无需阅读说明，就能找到“记录班次”。
- 默认路径没有出现销售额、到账方式、复杂规则或设置页面。
- 输入一个金额后，净收入立即且清楚地变化。
- 保存后有明确“已保存”反馈，月历和当天汇总同步更新。
- 删除具有确认和短暂撤销。
- 无记录、无 Tip-out、同日多班、跨午夜班次、输入错误均有完整状态。
- 关键按钮易于单手点按，关键金额在手机上无需放大即可阅读。

## 8. 应补充的状态页

以下是对四个主页面的补充状态，不新增产品能力；它们用于验证边界交互和错误恢复。

| 优先级 | 状态页 | 必须呈现的内容 |
|---|---|---|
| P0 | 首次使用／创建第一家餐厅 | 可跳过薪资与 Tip-out 设置；完成后立即能从日历记录班次 |
| P0 | 无记录日期的当天详情 | 空状态、简短说明和唯一主操作“Record a shift” |
| P0 | 编辑班次与删除确认／撤销 | 编辑保存反馈、删除确认、删除后的短暂撤销入口 |
| P0 | 更多选项展开 | Lunch／Dinner、Clock in／Clock out 二选一、未付休息、其他收入、自动 Tip-out；默认表单保持收起 |
| P1 | 自动 Tip-out 与同日多班 | 两条班次卡片及当日汇总；自动 Tip-out 的计算基数、比例、最终金额和可展开规则快照 |

## 9. 原型交付物

- 一份 Figma 文件，包含组件页、四个主页面、五个状态页及三条可点击流程。
- 使用真实感但明确为模拟的数据，以便检查金额层级与日历密度。
- 每个页面标注其对应的需求章节；开发前由产品确认默认快速记录路径。
